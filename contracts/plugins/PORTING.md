## 1. Що таке «плагін» у цій архітектурі

Застосунок **ніколи** не завантажує і не виконує твій код. Він робить HTTP-запит до твого сервера й отримує JSON.

```
користувач → Kadrbox → GET https://твій-сервер/api/v1/search?q=...
                              ↓
                         твій Node-сервер → fetch сайту
                              ↓
                         JSON назад → Kadrbox грає m3u8 напряму з CDN
```

Тому мова сервера — будь-яка. `Node + TypeScript` — рекомендація, і ось чому саме він:

**Go ніколи не мав шансів на Cloudflare.** У нас був `client.go` зі спофікацією TLS-відпечатка Chrome — це best-effort, який Cloudflare бачить і який ми не могли покращити принципово. У Node ти отримуєш **справжній браузерний** відпечаток, просто запустивши браузер.

## 2. Головна структурна зміна: два рівні.fetch

Це **не** переклад Go→JS. Go-код був один інструмент, бо ми вміли підробляти відпечаток. У Node їх два:

| Рівень | Коли | Що дає |
|---|---|---|
| `fetch` (undici) | прості сайти, DLE-каталоги | швидко, легко, без браузера |
| `playwright` / `puppeteer` | Cloudflare, JS-рендер, `data-lebclicks` | справжній TLS + виконує їхній JS |

**Правило:** спробуй `fetch`. Якщо 403 /挑战 / порожній DOM — одразу `playwright`. Не намагайся чинити `fetch` «смішнішим» — це шлях, яким ми вже пройшли в Go і який нічого не дав.

### Інтерфейс, який варто зробити першим

```ts
export interface FetchTier {
  get(url: string, opts?: { referer?: string; ua?: string }): Promise<string>;
  close?(): Promise<void>;
}

export function tierFor(host: string): FetchTier;   // де ти вирішуєш, який рівень
```

Далі всі адаптери працюють лише з `FetchTier` і не знають, чи це браузер.

## 3. Мапа Go → TypeScript

| Go | TS | Notes |
|---|---|---|
| `regexp.MustCompile` пакетно | модуль-константа | не компілюй regex у циклі |
| `strings.Builder` | масив `join` або template literal | — |
| `strconv.Atoi` | `Number.parseInt` + `Number.isFinite` | Go повертає error, JS — `NaN`. **Завжди перевіряй** |
| `context.Context` з таймаутом | `AbortSignal.timeout(ms)` | обов'язково на кожен запит |
| `io.ReadAll` + ліміт | `res.text()` + перевірка `content-length` | не читай необмежено |
| `html` tokenizer | `cheerio` | див. §6 — наївний селектор не працює |
| `encoding/charmap` windows-1251 | `iconv-lite` або `TextDecoder('windows-1251')` | див. §6 |
| `sync.Mutex` | не потрібен | Node однопотоковий, але запити паралельні — не зберігай стан у модульних змінних |
| `errors.Is` | власний `class AppError extends Error` з `code` | клієнт має відрізняти 404 від 500 |

## 4. Криптографія — два місця, де Go і JS різняться

Це найнебезпечніша частина. Обидва випадки перевірні тест-вектором із `testdata` **до** того, як писатиш обгортку.

### 4.1 uaserials: AES-256-CBC + PBKDF2-SHA512

Go робив це так: `pbkdf2.Key(sha512.New, password, salt, 999, 32)`, далі AES-CBC, ciphertext — base64, salt/iv — hex. Ключ живе в атрибуті `data-tag`.

```ts
import { pbkdf2Sync, createDecipheriv } from 'node:crypto';

export function decryptTag(tag: string, password: string): string {
  const [ctB64, saltHex, ivHex] = tag.split(':');
  const salt = Buffer.from(saltHex, 'hex');
  const iv   = Buffer.from(ivHex,   'hex');
  const key  = pbkdf2Sync(password, salt, 999, 32, 'sha512');
  const ct   = Buffer.from(ctB64, 'base64');

  const d = createDecipheriv('aes-256-cbc', key, iv);
  return Buffer.concat([d.update(ct), d.final()]).toString('utf8');
}
```

**Дві пастки, обидві реальні:**

1. **PKCS#7.** У Go ми розпаковували padding вручну. У Node `decipher.final()` **сам** перевіряє і знімає PKCS#7. Якщо ти додаси ручний `unpad` — отримаєш зламаний результат або помилку на останньому блоці. Не роби ручний unpad.

2. **`final()` кидає помилку** на некоректному padding. Тобто «просто не кидай» не працює — обгорни в try і поверни `null`, а не падай на всю сторінку.

**Ключ із бандла.** В оригіналі він лежав у обфускованому `fe68ee32.min.js`, і регулярка `var dd="..."` **ніколи не спрацювала**. У Node-порті не повторюй цей підхід: або витягни ключ одноразово в конфіг, або використай headless-браузер і візьми значення з живого DOM.

**Тест-вектор:** `testdata/uaserials_tag_vector.json`. Проганяй першим, до будь-якої обгортки.

### 4.2 tortuga: XOR

`testdata/tortuga_encoded_sample.txt` — зашифроване, `tortuga_roksolana.json` — результат. Це пара для round-trip.

**Три пастки, усі з маніфесту:**

1. **XOR по байтах, а не по rune.** У Go range по string ітерує UTF-8 руни, а не байти. У JS `for (const ch of s)` теж ітерує кодові точки. Для симетрії з байтовою логікою Go тобі потрібні `Uint8Array`, а не string-iteration. **Це найчастіша джерельна помилка порту.**

2. **Base64 із зрізаним padding.** Вхід не має `=` — додай сам, інакше `Buffer.from(x, 'base64')` відріже хвост.

3. **Latin-1, не UTF-8.** Результат XOR — це байти, які треба прочитати як latin1. У Node: `buf.toString('latin1')`. Якщо прочитаєш як utf8 — отримаєш replacement-символи.

Формат поля: `{dub}https://.../index.m3u8(subtitle:...)`. Dub — у фігурних дужках, subtitle — у дужках. Розбивай **до** нормалізації URL.

## 5. Кодування — windows-1251

У Node `TextDecoder('windows-1251')` **є** убудованим, окремий npm не потрібен. Але:

```ts
// так
const text = new TextDecoder('windows-1251').decode(buf);
// так НЕЧИТАВАТИ
const text = buf.toString('utf8');   // дасть replacement-символи на кирилиці
```

Не намагайся «полагодити» це регуляркою — замість кирилиці отримаєш `Ñ`.

## 6. Селектори: чому наївний підхід не працює

Три пастки, кожна з них уже коштувала нам реального часу.

**uakino** — плейлист вантажується **AJAX**. Статичний HTML сторінки не містить жодного сезону. `fetch` дасть порожній результат, і це **не** збій парсера. Перевіряй через `playwright` або знайди XHR-ендпоїнт.

**eneyida** — секції `serials` і `multfilmy` дають **404**. Каталог лежить на іншому шляху. І `.short_title` — це `<a>`, а не `<h2>`, як у всіх інших DLE.

**uaserials** — дві різні сторінки:
- сторінка **пошуку** → `a.uas-card` (18 карток)
- **каталог** → `.short-item`

І найжорстокіше: у назві однієї картки є `<mark>Роксолана</mark>`. Наївний селектор `([^<]*)` **обрізає** цю картку і втрачує рівно її — 17 замість 18. Не виправляй regex; витягуй текст через `cheerio` (`.text()`), а не регуляркою.

## 7. ashdi: не довіряй статус-коду

`/hls/1080/index.m3u8` повертає **200** з master-плейлистом, який вказує на 480p. Сегменти за 404-URL — це **ті самі** файли, що й за 200. Тобто:

> **Ніколи не конструюй шлях за якістю. Якість бери тільки з master-плейлиста.**

Це був один із найдорожчих багів: ми будували шлях `/hls/{quality}/` за назвою релізу й отримували порожнє відео.

Плюс окремо: `?geoblock=` вбиває відповідь — не додавай його.

## 8. Що портувати дослівно

Ці два файли не перекладай — переноси змістом:

**`studios_data.go` + `studios.go`** — словник 106 студій озвучення. Назви — це факти (`1+1`, `2+2`, `Postmodern`), витягнуті з дерева плейлистів. Двофазний резолв: спершу точний збіг, потім **найдовший** відомий аліас. Найдовший, а не перший — інакше `1+1` перехопить `1+1 Media`.

**`playerjs_scan.go` + `playlist_tree.go`** — це те, що дає сезони/епізоди/озвучки. `playerjs_scan.go` замінює регулярку, яка **ніколи не спрацювала** (вимагала `[` одразу після `file:` і забороняла `"` всередині; реальний HDVB пише `file: '[{"title":"1 сезон",…'`). У TS зроби так само — сканер глибини дужок, а не regex.

## 10. Порядок робіт

Роби строго в такому порядку. Кожен крок має бути зеленим перед наступним.

**Крок 0 — каркас.** `Node + TypeScript`, Fastify або Hono, ендпоїнти з `openapi.yaml`, **`/status` з `protocol_version: 1`**. Жодного адаптера. Сервер має запуститися.

**Крок 1 — фікстури.** Скопіюй `testdata/` у свій репозиторій. **Пиши тести проти них, перш ні писати парсер.** Мета: тест падає, бо функції ще нема.

**Крок 2 — `playerjs_scan` + `playlist_tree`.** Не DLE, а дерево PlayerJS. Перевір на `eneyida_player_hdvb.html`. Це спільна основа для всього, і коли вона зелена, будь-яка подальша помилка — це точно мережа або селектор, а не основа.

**Крок 3 — `tortuga_format` + XOR.** Round-trip на парі `tortuga_encoded_sample.txt` → `tortuga_roksolana.json`. Криптія — раніше, бо вона найдешевша для перевірки.

**Крок 4 — uaserials.** Найбільший файл (1199 рядків). AES через `uaserials_tag_vector.json` **до** парсингу HTML. Розкриття якостей — з master, ніколи з конструкції шляху.

**Крок 5 — DLE.** uakino, потім eneyida, потім lavakino. **uakino останній із «простих»**: він виглядає зламаним під час bring-up, бо плейлист через AJAX. Це не збій.

**Крок 6 — bandera.** Найбільша кількість полів і найменше цінності: це агрегатор, який сам робить фан-аут. Якщо щось і можна не портувати — це воно.

## 11. Рішення, яке треба закрити до кроку 4

**Хто кластеризує: сервер чи застосунок?**

Якщо кожен сервер кластеризує самостійно, то користувач із двома серверами побачить один фільм двічі. Тому **міжкаталогове злиття живе в застосунку**, а сервер повертає «як є, як знайшов».

Це означає: `search/` (`cluster.go`, `plan.go`, `score.go`, `confusables`) **не портуєш**. Вони працюють у Kadrbox.

Потрібна відповідь від розробника Kadrbox, чи це так. Поки що роби так, наче так.

## 12. Операційка, про яку забувають

**Твій IP — не наш.** Kadrbox більше ніколи не ловить бан за скрейпінг, бо він не скрейпить. Усеanti-ban — твоя проблема: ротація, резидентні проксі, кеш.

**Будь добрим до своїх клієнтів.** Застосунок кешує `/details`, але **не** кешує `/search` і **`/streams`**. Тисяча користувачів на одному сервері — це тисяча пошуків наживо. Кешуй у себе, інакше тебе заблокують.

**Помилки.** Розрізняй `404` (немає такого) і `502` (сайт лежить). Застосунок показує статус кожного сегмента, і мовчки прибрати збійний сегмент — найгірше, що можна зробити: користувач вирішить, що каталог порожній.

**Юридична відповідальність — твоя.** Ти вирішуєш, які джерела віддаєш. Kadrbox не має жодного каналу, яким їх роздавати.

## 13. Чекліст готовності адаптера

- [ ] помилки розрізнені: 404 / 502 / таймаут
